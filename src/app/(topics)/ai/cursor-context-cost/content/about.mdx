**필요한 맥락만 정확히 줍니다.** 관련 파일과 오류, 무엇이 성공인지를 지정하는 편이
폴더를 통째로 던지는 것보다 낫습니다. 다만 Cursor 문서는 **어느 파일이 관련 있는지
알 때** `@` 로 짚으라고 권합니다. 모르겠으면 짚지 말라고요 — Agent 가 스스로 찾습니다.

**작업 경계가 바뀌면 새 채팅을 고려합니다.** 요약은 같은 대화 안에서 자리를 만들 뿐,
이전 작업의 지시와 도구 결과를 치워 주지는 않습니다. 새 작업에 도움이 되지 않는 문맥이
쌓여 있다면 짧은 출발점이 더 예측하기 쉽습니다.

**호출 수도 문맥만큼 봅니다.** 호출마다 그때까지의 문맥이 통째로 다시 실리므로, 호출이
늘면 누계도 함께 늘어납니다. 위 화면에서 시작 문맥은 그대로 두고 호출 수만 늘려 보세요 —
호출마다 붙는 결과가 있으면 누계는 호출 수보다 빠르게 자라고, 붙는 결과가 없으면 호출
수에 비례해 자랍니다. 한 번에 될 일을 여러 번 되돌아가게 만드는 모호한 요청이 여기에
그대로 나타납니다.

**링과 대시보드를 나눠 봅니다.** 링은 지금 이 채팅이 한도에 얼마나 가까운지를 말하고,
대시보드는 이미 처리된 양과 비용을 말합니다. 링이 낮다고 누계가 낮은 것도 아니고,
누계가 크다고 한 호출이 창을 넘긴 것도 아닙니다.

제품 화면과 모델 목록, 요율은 바뀝니다. 이 글이 남기려는 것은 특정 시점의 숫자가 아니라
**어느 수가 어느 질문에 답하는지 가려내는 법**입니다.

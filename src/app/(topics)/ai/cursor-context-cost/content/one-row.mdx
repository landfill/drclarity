export const title = '대시보드의 한 행은 무엇인가';

한 사용자의 Usage 자료에서 가장 큰 행은 이랬습니다. 새 입력 101,586 ·
캐시 읽기 4,087,130 · 출력 19,542, 그리고 Total 이 <strong>4,208,258</strong>.

이 자료에는 캐시 쓰기 열이 없어서 세 값뿐이고, Total 이 정확히 그 셋을 더한 것입니다.
우연이 아니라 정의가 그렇습니다 —
Cursor SDK 문서는 `totalTokens` 를 `inputTokens + outputTokens + cacheReadTokens +
cacheWriteTokens` 로 정의합니다. 즉 이 칸은 <strong>한 번에 들어간 문맥의 크기가 아니라
청구 항목의 합</strong>입니다. 그래서 이 420만은 420만짜리 문맥도, 사용자의 월간
누적도 아닙니다.

그럼 한 행은 어디까지를 묶은 것일까요. Cursor 직원이 공식 포럼에서 이렇게 설명했습니다 —
메시지 하나가 보통 여러 번의 모델 호출을 만들고, 그것들이 **대시보드의 한 행으로 합쳐지며,
합산은 요청이 끝날 때(다시 입력할 수 있게 될 때) 멈춘다**고요. 이 설명대로라면 한 행은
대체로 사용자 요청 한 번, 곧 Agent 한 턴입니다.

다만 이것을 모든 행에 대한 보증으로 쓰지는 않겠습니다. 같은 회사의 Admin API 문서는
usage event 를 모델 호출 단위로 설명하고, SDK 는 턴이 끝날 때마다 그 턴의 사용량을
내보냅니다. 표면마다 묶는 단위가 다를 수 있고 export 스키마도 바뀝니다. 어느 행들이 한 채팅에
속하는지 묶으려면 세션 ID 나 request ID 가 있어야 하는데, 자료에 그 열이 없으면
근거로 삼을 것이 남지 않습니다.

그래서 행 수를 그대로 메시지 수로 읽지 않는 편이 안전합니다. 무료로 처리된 사용량이
행에 남는지, 자동 실행이나 재개가 별도 행이 되는지, 서브에이전트의 토큰이 부모 턴에
합산되는지 별도 이벤트가 되는지는 자료마다 다를 수 있습니다.

확실한 것은 단위가 무엇이든 바뀌지 않는 쪽입니다. **행의 Total 은 항목의 합이고,
창 한도와 비교할 값이 아닙니다.**

같은 화면에 보이는 숫자들이 서로 다른 질문에 답합니다. 어느 질문에 답하는 수인지를
먼저 정하면 나머지는 따라옵니다.

**입력칸의 링과 breakdown — 활성 컨텍스트.**
지금 이 채팅의 다음 호출에 실릴 문맥이 창을 얼마나 차지하는가.

**한 번의 모델 호출 — 새 입력 · 캐시 쓰기 · 캐시 읽기 · 출력.**
이번 한 번의 호출에서 각 항목이 얼마였는가. 앞의 셋은 입력을 겹치지 않게 나눈 조각이고,
셋을 더하면 그 호출의 입력 문맥이 됩니다.

**Usage 대시보드 — 여러 호출의 항목 합계.**
이 요청 또는 이 기간에 처리된 양과 비용이 얼마인가.

여기서 나오는 규칙이 하나 있습니다. <strong>창 한도와 비교할 수 있는 것은 첫째 줄뿐입니다.</strong>
정확히는 첫째 줄에 **그 호출이 만들 출력까지 더한 값**입니다 — 컨텍스트 창은 모델이 한 번에
고려하는 입력과 생성 출력의 범위이므로, 입력만 보면 출력이 창을 밀어내는 경우를 놓칩니다.

셋째 줄은 항목을 더한 값입니다. 출력이 함께 들어 있고 호출마다 문맥이 겹쳐 다시 세지므로,
그 합만 한 문맥이 모델에 들어갔다고 볼 근거가 되지 못합니다.

그래서 <strong>누계가 창보다 크다는 것 자체는 한도를 넘겼다는 신호가 아닙니다.</strong>
호출이 여러 번이면 빠르게 커지고, 호출이 한 번이어도 출력이 붙으면 창을 넘길 수 있습니다.
한도를 넘겼는지는 첫째 줄로만 판단합니다.

링의 breakdown 에는 대화만 있는 것이 아닙니다. Cursor 문서는 시스템 지시, 도구 정의,
규칙, Skills, MCP, 서브에이전트 문서, 요약된 대화, 대화를 항목으로 듭니다. 새 채팅을
열어도 링이 0 에서 시작하지 않는 것은 이 때문입니다.
